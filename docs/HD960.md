# 960×720 主工程移植说明

已从验证通过的 dmz_track1_hd960 副本移植到主工程 dmz_track1，将图片解码、双帧缓存和课件图层接入960×720中央显示区，HDMI输出仍为1280×720。侧栏、字幕、按钮、答题及连播规则保留。

## 实现
- BMP：原生960×720或其他尺寸等比例适配，RGB565，每帧691200像素。
- 帧A：SDRAM字节0～1382399；帧B：2097152～3479551。
- SCENE配置/字模：字节4194304起，最多1MiB，避免与扩大的帧缓存重叠。
- SDRAM保留打开行以提高连续读取效率，换行时预充电，刷新前关闭全部行；仍为50MHz，未通过升频解决带宽问题。
- 背景原生逐像素输出；课件配置仍使用640×480逻辑坐标，加载时将按钮图层映射到高清帧，兼容现有TF课件包。
- 水平擦除仍为10步，每步48个32位字即96像素。

## 本轮仿真证据
- docs/hd960/：此前高清解码8项案例；默认640×480兼容案例另见docs/scaler*。
- docs/widescreen_sim_result.txt：两帧1382400像素逐像素对照，实际SDRAM控制器/模型、刷新、共享总线额外访问、FIFO无欠载、48kHz采样节拍。
- docs/page_compositor_result.txt：两种BMP行方向、五个中文控件、691200像素图层合成、背压。
- docs/wipe_sim_result.txt：10步擦除、旧新银行选择、交换时刻、后台帧保护。
- docs/scene_runtime_result.txt：配置迁至4MiB后的真实CRC、课件流程、计分与通知恢复。
- docs/p2_sim_result.txt：8MiB四种模式共8388608次字校验，以及读写/刷新显示检查。

## 构建与上板
运行 scripts/build_system.ps1；必须通过最终布线时序检查后才运行 scripts/download_system.ps1。下载目标为本目录内生成的bit文件。当前构建与硬件验收进度见 docs/hd960/validation.json，旧的复制文档不能作为本次实验的验收证据。

现有640×480图片也可播放，但增加真实细节需要高分辨率原始素材；把原图片放大不等于恢复细节。尚未操作Flash，SRAM下载后掉电仍需重新下载。
